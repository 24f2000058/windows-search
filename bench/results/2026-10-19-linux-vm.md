# Benchmark run — 2026-10-19 (development VM, NOT the Windows reference PC)

Machine: cloud VM, 4 vCPU Intel Xeon @ 2.80 GHz (1 thread/core), 15 GiB RAM,
Linux 6.18, rustc 1.97.0, g++ 13.3.0, clang++ 18.1.3. Shared/noisy host:
expect ±15% run-to-run variance. Release profile (thin LTO, codegen-units=1),
no `target-cpu` tuning on either side.

Reproduce:

```sh
cargo build --release -p flint-bench
./target/release/flint-bench engine --n 1000000 --queries 200
./target/release/flint-bench engine --n 100000  --queries 200
./target/release/flint-bench index  --n 1000000
./target/release/flint-bench dump --n 200000 --out names.txt
./target/release/flint-bench kernels --corpus names.txt
g++     -O3 -std=c++17 bench/cpp/kernels.cpp -o k_gcc   && ./k_gcc   names.txt
clang++ -O3 -std=c++17 bench/cpp/kernels.cpp -o k_clang && ./k_clang names.txt
```

## Rust vs C++ (single-threaded kernels, identical algorithms)

150 queries (typo/scattered/nonsense) × 200,000 folded names; Hyyrö OSA
approximate-substring + subsequence-with-positions per pair. Hit counts were
identical in every run (osa_hits=149314, sub_hits=418694).

| Implementation | ns / name-pair (2 runs) |
|---|---|
| Rust            | 164.1, 164.2 |
| C++ (g++ -O3)   | 159.1, 159.2 |
| C++ (clang -O3) | 160.0, 159.4 |

Note: a first C++ port omitted tracking the best-match end position and
appeared 25% faster (clang 128–137 ns); the faithful port removed the gap.

## Search engine (4 threads), synthetic corpus, warm, default options

Default = best-effort on, exhaustive off, `enough`=50, limit 500. "first p95" =
time until the first ranked snapshot. Completion includes all weaker stages
needed to reach 50 matches.

## Memory (1,000,000 entries)

Name table heap ≈ 102 MB by capacity accounting; RSS delta 73.8 MB after
build (~75 bytes/entry incl. names). Exceeds the provisional 50 MB idle target
at this scale — see docs/decisions.md (open item).
